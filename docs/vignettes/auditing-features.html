Auditing Feature Matches

Inspect exact and sentence-level feature evidence with audit_features() using pre-parsed UDPipe data. 
library(pseudobibeR.fr)
library(udpipe)
library(dplyr)
library(stringr)

load("../data/french_corpus.rda")   # loads 'french_corpus'
load("../data/fc_udpipe_parsed.rda")   # loads 'fc_udpipe_parsed'

discipline_lookup <- french_corpus |>
  distinct(doc_id, discipline)

Why audit feature matches?

biber() gives you document-level counts. audit_features() lets you step down to the sentence or token span that triggered those counts so you can review edge cases, confirm parser behavior, and share examples with collaborators.

The audit API now supports three common review modes:

  • Inspect a single feature with exact KWIC-style anchors when available
  • Sample a whole feature category without reading every sentence in the corpus
  • Distinguish between exact token-span matches and sentence-level fallback rows
NoteData

This vignette uses the Chambers-Le Baron UDPipe parse stored in _quarto/data/fc_udpipe_parsed.rda, plus the companion document metadata in _quarto/data/french_corpus.rda.

Audit a whole category

  max_per_doc = 2,
  seed = 7,

Compare exact and sentence-level review modes

Review reduced forms and negation together

You can also pass a vector of specific features when you want a targeted review set for debugging or annotation meetings.

targeted_audit <- audit_features(
  fc_udpipe_parsed,
  feature = c(
    "f_60_that_deletion",
    "f_61_stranded_preposition",
    "f_62_split_infinitive",
    "f_63_split_auxiliary",
    "f_66_neg_synthetic",
    "f_67_neg_analytic"
  ),
  sample_n = 14,
  max_per_doc = 2,
  seed = 21,
  window = 7

Practical review tips

  • Use sample_n when a feature is common enough that full inspection would be noisy
  • Use max_per_doc to avoid letting one document dominate the sample
  • Increase window for multiword constructions such as negation or split auxiliaries
  • Join audit output back to corpus metadata so reviewers can stratify by discipline, register, or source
  • Reserve biber() for quantitative summaries and audit_features() for qualitative spot-checking

Next step

Once you have confirmed that feature matches look sensible, return to biber() for corpus-level counts or move on to the multidimensional analysis workflows shown in the other vignettes.
