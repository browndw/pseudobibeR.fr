# Contributing to pseudobibeR.fr

Thank you for your interest in contributing! This guide will help you understand the package structure and development workflow.

## Quick Start

1. Clone the repository
2. Install development dependencies:

   ```r
   install.packages(c("devtools", "testthat", "roxygen2", "yaml"))
   ```

3. Load the package: `devtools::load_all()`
4. Run tests: `devtools::test()`
5. Check package: `devtools::check()`

## Package Structure

### Core Code (`R/`)

The main feature extraction code is modularized:

- **`parse_functions.R`** - Main `biber()` interface and orchestration
- **`utils_extraction.R`** - Helper functions (normalization, NA handling)
- **`features_*.R`** - Feature extraction blocks by linguistic category:
  - `features_tense_pronouns.R` - Tense, aspect, pronouns
  - `features_passive.R` - Passive voice
  - `features_subordination.R` - Clauses, relatives, participles
  - `features_modals_verbs.R` - Modals, specialized verbs
  - `features_coordination_negation.R` - Coordination, negation, contractions

All internal functions use `@keywords internal` to keep the API clean.

### Data Sources (`data-raw/`)

**YAML Configuration Files:**

- `dict.yaml` - Dictionary patterns for lexical features
- `word_lists.yaml` - Support lists (pronouns, suffixes, etc.)
- `french_examples.yaml` - Test examples with expected counts
- `french_edge_cases.yaml` - Complex linguistic constructions for regression testing

**Build Scripts:**

- `build_french_dictionaries.R` - **Run this after editing YAML files**
- `generate_edge_case_fixture.R` - **Run this after editing edge cases**
- `build_french_samples.R` - Rebuild corpus samples (optional)

See [`data-raw/README.md`](data-raw/README.md) for detailed documentation.

### Tests (`tests/testthat/`)

- `test-french-examples.R` - Validates feature extraction against examples
- `test-french-edge-cases.R` - Regression tests for complex constructions
- `test-input-validation.R` - Error handling and edge case inputs
- `test-french-*.R` - Feature-specific tests
- `fixtures/` - Test expectations generated by build scripts

## Development Workflow

### Adding a New Lexical Feature

1. **Update the dictionary** (`data-raw/dict.yaml`):

   ```yaml
   f_XX_new_feature:
     - term_one
     - term_two
     - multiword_expression  # use underscores
   ```

2. **Add examples** (`data-raw/french_examples.yaml`):

   ```yaml
   - feature: f_XX_new_feature
     example: Example sentence with the feature.
     count: 1.0
   ```

3. **Rebuild package data**:

   ```r
   source("data-raw/build_french_dictionaries.R")
   ```

4. **Update documentation**:

   - Add feature description to `biber()` documentation in `R/parse_functions.R`
   - Follow existing format with `\describe{}` and `\item{}`

5. **Test and check**:

   ```r
   devtools::document()
   devtools::test()
   devtools::check()
   ```

### Adding a Pattern-Based Feature

For features requiring custom logic (not just dictionary lookup):

1. **Identify the appropriate module** based on linguistic category

2. **Add the extraction function**:

   ```r
   #' Extract feature f_XX_new_feature
   #' @param tokens Token data frame
   #' @param doc_ids Document IDs
   #' @return Data frame with doc_id and feature count
   #' @keywords internal
   block_new_feature_fr <- function(tokens, doc_ids) {
     # Your extraction logic here
     result <- tokens %>%
       dplyr::filter(your_conditions) %>%
       dplyr::group_by(.data$doc_id) %>%
       dplyr::tally()
     
     # Ensure all documents represented
     doc_ids %>%
       dplyr::left_join(result, by = "doc_id") %>%
       dplyr::mutate(f_XX_new_feature = dplyr::coalesce(.data$n, 0L)) %>%
       dplyr::select("doc_id", "f_XX_new_feature")
   }
   ```

3. **Call the function** in `parse_biber_features()`:

   ```r
   df$f_XX <- block_new_feature_fr(tokens, doc_ids)
   ```

4. **Add edge cases** (`data-raw/french_edge_cases.yaml`):

   ```yaml
   new_feature_construction:
     - Sentence demonstrating the feature.
     - Another example sentence.
   ```

5. **Regenerate fixtures**:

   ```r
   source("data-raw/generate_edge_case_fixture.R")
   ```

6. **Test thoroughly**:

   ```r
   devtools::test()
   ```

### Fixing a Bug in Feature Extraction

1. **Add a failing test** to demonstrate the bug:

   ```r
   test_that("feature X detects construction Y", {
     # Minimal example that currently fails
   })
   ```

2. **Fix the extraction logic** in the appropriate `features_*.R` file

3. **Update edge cases** if the bug affects complex constructions:
   - Add case to `french_edge_cases.yaml`
   - Run `source("data-raw/generate_edge_case_fixture.R")`

4. **Verify the fix**:

   ```r
   devtools::test()
   devtools::check()
   ```

## Code Style

- **Use tidyverse style**: Run `lintr::lint_package()` before committing
- **Document all functions**: Even internal ones need `@param` and `@return`
- **Use `.data$column`**: For NSE in dplyr to avoid R CMD check notes
- **Keywords internal**: Add `@keywords internal` to non-exported functions
- **No ASCII violations**: Use Unicode escapes (`\u00e9`) for accented characters in code

## Testing Guidelines

### Writing Good Tests

- **One concept per test**: `test_that("specific behavior")`, not "everything works"
- **Use meaningful examples**: French sentences that clearly demonstrate the feature
- **Test edge cases**: Empty inputs, single tokens, punctuation-only
- **Check error messages**: Validate that bad inputs fail gracefully

### Running Tests

```r
# All tests
devtools::test()

# Specific file
devtools::test(filter = "french-modals")

# With coverage
covr::package_coverage()
```

### Test Data

- **Use package samples**: `spacy_samples`, `udpipe_samples` for realistic data
- **Create minimal examples**: For unit tests, use smallest reproducing input
- **Don't commit large test files**: Use `data-raw/` and `.Rbuildignore`

## Submitting Changes

### Before Creating a Pull Request

1. **Run the full check**:

   ```r
   devtools::check()
   ```

   Must show: `0 errors ✔ | 0 warnings ✔ | 0 notes ✔`

2. **Update documentation**:

   ```r
   devtools::document()
   ```

3. **Run tests**:

   ```r
   devtools::test()
   ```

   All tests must pass.

4. **Update NEWS** (if applicable):
   - Add entry under "Development version" section
   - Note new features, bug fixes, or breaking changes

5. **Commit message format**:

   ```
   Brief summary (50 chars or less)
   
   More detailed explanation if needed. Explain why the change
   was made, not just what changed.
   
   Fixes #123 (if applicable)
   ```

### Pull Request Checklist

- [ ] R CMD check passes (0/0/0)
- [ ] All tests pass
- [ ] Documentation updated
- [ ] NEWS.md updated (if user-visible change)
- [ ] Data rebuilt if YAML files changed
- [ ] Test fixtures regenerated if needed

## Getting Help

- **Package questions**: Open an issue with `[Question]` tag
- **Bug reports**: Include minimal reproducible example
- **Feature requests**: Describe use case and expected behavior

## Recognition

Contributors will be acknowledged in:

- Package `DESCRIPTION` file (for significant contributions)
- Release notes in `NEWS.md`
- Package documentation

Thank you for contributing to pseudobibeR.fr!
